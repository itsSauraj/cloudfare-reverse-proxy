# 🌐 Developer Gateway

Dynamic Cloudflare Worker reverse proxy that serves multiple independent
frontend apps under **path prefixes on a single domain** — without any app
knowing about the others, and without a redeploy when apps are added.

```
https://saurabh-yadav.me/            → portfolio
https://saurabh-yadav.me/youtube     → youtube clone
https://saurabh-yadav.me/icebox      → icebox
https://saurabh-yadav.me/novafetch   → novafetch
```

The existing subdomains (`yt.`, `icebox.`, `novafetch.` …) keep working — path
routing on the apex is purely additive.

---

## How it works

```
Request → Worker → Route Registry → match longest prefix → strip/forward → app
```

1. **Registry** (`registry.ts`) — an array of `{ id, route, target, enabled, stripPrefix?, rewriteHtml? }`.
   Read from a local `routes.json` in dev, or Cloudflare KV (key `apps`) in prod,
   selected by the `REGISTRY_SOURCE` var. Cached per-isolate for 60s with a
   keep-last-good fallback, and every `target` is validated http/https.
2. **Router** (`router.ts`) — boundary-aware longest-prefix match. `/youtube`
   matches `/youtube` and `/youtube/...` but **not** `/youtubeXYZ`; `/` is the
   catch-all. Disabled routes are skipped.
3. **Proxy** (`proxy.ts`) — anchored prefix strip, correct `Host` handling for
   Vercel-style origins, `X-Forwarded-*` headers, streamed response, optional
   HTML rewrite.

## Project layout

```
src/
  index.ts     orchestrator: admin → self-health → registry → route → proxy → 404/502
  types.ts     Route, HealthResult, LogRecord
  registry.ts  load (local | KV), normalize/validate, TTL cache, keep-last-good
  router.ts    matchesPrefix + findRoute (pure)
  proxy.ts     subrequest, headers, streaming, rewrite hook
  rewrite.ts   opt-in HTMLRewriter fallback
  cache.ts     generic in-isolate TTL memo
  health.ts    per-app /health probes
  admin.ts     token-guarded /__gateway/* endpoints
  log.ts       request id + structured JSON logs
routes.json    local dev registry
wrangler.jsonc, tsconfig.json, package.json
worker-configuration.d.ts   generated by `wrangler types` (committed)
```

## Local development

```bash
npm install
npm run dev            # wrangler dev on http://localhost:8787
```

`.dev.vars` sets `REGISTRY_SOURCE=local`, so the bundled `routes.json` is used.
Run your apps on `localhost:3000` / `3001` / `3002` / `3003` (or edit the
targets in `routes.json`), then:

```
http://localhost:8787/            → portfolio (3000)
http://localhost:8787/youtube     → youtube  (3001)
http://localhost:8787/icebox      → icebox   (3002)
http://localhost:8787/novafetch   → novafetch(3003)
```

> On Windows PowerShell, `curl` is an alias for `Invoke-WebRequest`. Use
> `curl.exe` for the examples in this README.

Admin endpoints (bearer token from `.dev.vars`):

```bash
curl.exe -s http://localhost:8787/__gateway/routes -H "authorization: Bearer dev-token"
curl.exe -s http://localhost:8787/__gateway/health -H "authorization: Bearer dev-token"
```

## Asset paths (important)

An app mounted at `/youtube` that assumes it lives at `/` will emit root-absolute
URLs like `/assets/main.css`, which the browser resolves against the apex and the
gateway can't route back to the app.

**Default / recommended:** configure each app with a matching base path and set
`stripPrefix: false` for its route (the full path is forwarded, so the app's own
absolute URLs already resolve):

| Framework | Setting                                          |
| --------- | ------------------------------------------------ |
| Next.js   | `basePath: "/youtube"` (+ `assetPrefix`)         |
| Vite      | `base: "/youtube/"`                              |
| CRA       | `"homepage": "/youtube"`                         |

**Fallback:** for an app you can't reconfigure, set `stripPrefix: true` and
`rewriteHtml: true`. The gateway strips the prefix and rewrites root-absolute
attribute URLs in the HTML. This is **best-effort** — it cannot fix runtime
`fetch()`/`import()`, framework chunk loading, `srcset`, CSS `url()`, import maps,
or a page-set `<base href>`. See `rewrite.ts`.

> Single-origin note: all apps share the apex origin, so cookies without an
> explicit `Path` and `localStorage`/`sessionStorage` are shared. Scope cookies
> (`Path=/youtube`) and namespace storage keys per app.

## Deploying to production

These steps require your Cloudflare account and are **not** run by the build.

1. **Create the KV namespace** and paste the ids into `wrangler.jsonc`
   (`kv_namespaces[0].id` / `preview_id`):

   ```bash
   wrangler kv namespace create ROUTES
   wrangler kv namespace create ROUTES --preview
   ```

2. **Seed the registry** (production targets, e.g. `https://*.vercel.app`):

   ```bash
   wrangler kv key put --binding ROUTES apps --path routes.json --remote
   ```

   (Local dev store, if you want to exercise the KV branch locally:
   `wrangler kv key put --binding ROUTES apps --path routes.json --local`.)

3. **Keep `REGISTRY_SOURCE=kv`** in `wrangler.jsonc` `vars` (already the default).
   `.dev.vars` keeps `wrangler dev` on `local`.

4. **Set the admin secret:**

   ```bash
   wrangler secret put ADMIN_TOKEN
   ```

5. **Bind the Worker to the apex host only** — uncomment in `wrangler.jsonc`:

   ```jsonc
   "routes": [
     { "pattern": "saurabh-yadav.me/*", "zone_name": "saurabh-yadav.me" }
   ]
   ```

   `saurabh-yadav.me/*` matches the apex only, so `yt.saurabh-yadav.me` and other
   subdomains are untouched. Ensure the apex DNS record is **proxied** (orange
   cloud) so the route can attach.

6. **Deploy:**

   ```bash
   npm run deploy
   ```

7. **Watch logs:** `npm run tail`.

### Adding an app later

Edit the registry (KV `apps` value, or `routes.json` + re-seed) — no code change,
no redeploy. Propagates within the 60s cache TTL.

```bash
wrangler kv key put --binding ROUTES apps --path routes.json --remote
```
